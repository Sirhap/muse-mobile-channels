# 微信、企业微信接入 Muse

本教程对应 [飞书图文教程](https://my.feishu.cn/docx/SsDMdusWboCxOrxJJD7c6Z2xngc)，手机操作截图请查看飞书原文。个人微信和企业微信可以只接一边，也可以同时接入；两条渠道的历史分别保存。

默认部署使用 legacy 模式。SQLite core 模式目前只用于文本实验，不能替代完整的生产功能。

## 发给 Muse 的安装提示词

```text
请帮我在这台 Muse 虚拟机上安装或检查 https://github.com/Sirhap/muse-mobile-channels，让我通过个人微信或企业微信对话。

先问我要接哪一边：个人微信、企业微信，或两者都接。只配置选中的渠道；需要扫码或身份信息时等我提供，不猜测，也不要在聊天、日志或代码仓库中输出凭证。

先检查现有安装、工作区改动、运行中的任务和服务。读取当前仓库 main 的 README.md、所选渠道的配置以及 docs/bridge-failover-2026-11-01.md，按实际版本安装；已有部署先说明将修改的服务和恢复方式，取得我的同意后再执行可能影响生产的变更。保持完整仓库结构。项目多处使用 /home/hatch/workspace 绝对路径；不同路径须逐项核对代码、钩子和服务配置。默认使用 legacy；core 仍是文本实验模式。

每个渠道的依赖命令都从仓库根目录独立执行，只执行我选择的渠道：
个人微信：python3 -m venv weixin-bot/.venv && weixin-bot/.venv/bin/pip install -r weixin-bot/requirements.txt
企业微信：python3 -m venv wecom-bot/.venv && wecom-bot/.venv/bin/pip install -r wecom-bot/requirements.txt

个人微信按 login.py 提示出二维码，由我扫码；若要求验证码，在同一登录会话提交。企业微信使用官方智能机器人 API 长连接；按实际凭证文件配置 Bot ID、Secret 和 WECOM_ALLOW_USERS，白名单为空会拒绝入站。不要让我把凭证直接贴进聊天，使用环境支持的安全方式提供。

按 README 和仓库服务定义配置选中的网关、原生桥与收件钩子。只为选中渠道启用对应开关；注册钩子须通过平台 hooks API，poll_interval_secs 不小于 5。确认桥的运行依赖、凭证与实际路径，不要假定服务 active 就代表端到端可用。

如需手机审批，按 README 配置 approval-relay 和明确的会话、操作者授权；普通消息白名单不自动授予审批权限。先核实当前部署读取 APPROVAL_ADMINS_JSON 的服务环境以及实际会话/操作者 ID；不要猜或在聊天中打印这些值。无法核实时告诉我。

完成后报告安装版本、所选服务及未完成项；让我在每个已启用渠道先发 /ping，再发一条普通问题。两者分别确认网关连通与正式回复。进一步测试参照 docs/muse-live-test-cases-2026-11-01.md；不要在未获同意时停止生产服务或修改在途状态。
```

## 工作方式

微信和企业微信网关接收消息后，将其交给 Muse，回复再回到原渠道。默认 legacy 模式下，启用并接管渠道后，符合条件的单聊文字走原生桥；图片、文件、语音及群聊走收件钩子。桥不可用时，只有状态允许安全切换才进入备用路径。

## 个人微信扫码

1. 在微信依次打开「我」→「设置」→「插件」→「微信 ClawBot」→「详情」。
2. 选择「连接新的 OpenClaw」，点击「开始扫一扫」，扫描 Muse 生成的 `login-qr.png` 并确认。
3. 终端出现 `LOGIN CONFIRMED` 表示绑定成功。若要求验证码，在同一登录会话中提交；二维码过期后重新生成。

微信页面中提到的 OpenClaw 是插件原文案，本仓库直接实现 iLink 协议，不需要执行页面提供的 OpenClaw 安装命令。微信页面说明回复有时间窗口，具体以微信当前页面为准。操作截图见[飞书图文教程](https://my.feishu.cn/docx/SsDMdusWboCxOrxJJD7c6Z2xngc)。

## 企业微信配置

在企业微信依次打开「通讯录」→「智能机器人」→「创建」→「创建智能机器人」→「API 模式」，选择长连接，获取 Bot ID 和 Secret。通过环境支持的安全方式交给 Muse，写入仓库外的凭证文件。

网关还需要 `WECOM_ALLOW_USERS`，填写获授权的企业微信用户 ID，多个用逗号分隔；为空时拒绝入站。这个白名单不自动授予审批权限。机器人主动推送前，需要核实平台要求及目标会话路由。视频发送上限为 10MB，网关会先尝试压缩，仍超限时会提示未发送。

## 桥凭证

桥凭证保存在仓库外。需要导出或更新 token 时，按 [桥凭证恢复说明](../native-bridge/get-muse-token.md) 和 [导出脚本](../native-bridge/get-muse-token.js) 操作。导出的 JSON 等同登录凭证，不要贴进聊天、日志或仓库。

## 日常使用

- `/ping`：检查手机到网关的连通性，不代表 Muse 已完成普通任务。
- `/status`、`/check`：查看状态；进程在线不能单独证明桥和投递端到端可用。
- `/queue`、`/queue clear`、`/queue drop N`：查看或管理尚未开工的排队任务。
- `/stop`：登记取消请求；是否停止以执行方确认或实际结果为准。
- `/new`：切换上下文；原生桥在下一条走桥的文字到来时创建新会话。
- `/subagent <任务>`、`/subagent list`、`/subagent stop <编号>`：派发、查看或停止副助手。
- `/help`：查看当前版本的完整命令表。

进度、排队或思考提示不表示任务完成；正式回复与文件发送应以实际投递结果为准。手机审批需要配置审批中转以及明确的会话、操作者授权；提交结果不明时先在 Muse 中核查，不重复批准。

## 故障排查

如果 `/ping` 通但普通消息没有正式回复，或出现桥断线、自动重连暂停、提交结果待核查，可以把下面的话发给 Muse：

```text
请先只读检查当前仓库版本和运行模式、选中渠道的网关/桥/hook 服务、桥心跳、降级标记、任务队列与投递结果。请区分已入队、平台已接收、实际显示和结果不明，汇报发现及建议。不要输出凭证、用户 ID 或聊天正文；不要重发可能已经执行的任务，不要删除状态、清除 fallback 标记或重启服务。任何可能影响现有任务的操作先给出计划并征得我同意。
```

桥切到备用路径后不会自动切回。确认备用任务及投递已结案、没有未知提交或积压后，再按 [桥故障恢复说明](bridge-failover-2026-11-01.md) 制定恢复操作。结果不明时应核查原任务，不能仅因为没看到回复就重发。

## 验收

每个启用的渠道先发送 `/ping`，再发送普通问题，分别确认网关连通和正式回复。完整用例见 [Muse 实测用例](muse-live-test-cases-2026-11-01.md)。故障注入应在隔离环境执行，涉及生产服务的操作须先取得同意。
