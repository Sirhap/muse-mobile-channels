# 渠道提示词与聊天文案优化

日期：2026-11-01；分支：`refactor/reliable-channel-core`。

两份 hook 提示词改为中文，微信从 17,283 字符缩减为 4,129 字符，企微从 16,880 字符缩减为 4,139 字符。删除重复事故回顾与历史政策，按输入、活动、顺序、回复、交接、副助手及权限边界组织规则。

修正以下行为描述：

- 普通任务没有总时长上限，但失去真实活动证据后仍可能被恢复或停止。
- orphaned 不一定首次执行；结合 resume、resumed_msgids 和 job_retry 核查已有成果，避免重复副作用。
- CLI 入队成功、平台接收确认和用户已读分别描述；results 中无记录不触发重复回复。
- 取消登记不等于操作已终止；交接登记不等于主会话已接手。
- 副助手通知必须核实原任务会话归属；不能直接转发给恰好触发本次唤醒的聊天。
- 微信不主动发送上下文压缩通知；字符预算不误称字数或 token 数。
- 保留 heartbeat、run_id、hold、取消检查、文件非空、迟到补答、特殊回复首行和基础设施边界。

聊天文案同步优化 `/new`、`/stop`、审批登记及文件失败反馈，明确生效条件和下一步，避免已完成或立即完成的保证。

验证：JSON 解析通过，逐字段比较确认 hook 定义仅 prompt 变化；命令审计 59 项、审批别名 151 项通过；13 组核心沙箱套件全部通过（178 项检查），`git diff --check` 通过。模型遵循提示词的效果尚未做真实渠道验收。

本次修改仓库模板。线上 hook 定义须通过平台 hooks API 更新，部署前按项目约定确认。后续应在沙箱回放普通问题、恢复任务、群聊通知、取消和交接，验证实际交互。

## 原生桥断线与重复连接

补充检查确认，旧实现只统计 connect() 失败，并在握手成功时立即清零；连接成功但历史查询持续失败时，实际会一直连接。普通连接失败也缺少退避。故障通知每小时重复，且“自动重连，你不用管”与三次失败后暂停的策略矛盾。

现已按真实操作结果计数：握手成功不清零，任务启动、任务轮询或历史查询成功才恢复；普通失败退避 5 秒、10 秒，连续三次失败暂停，认证错误保留 600 秒等待。凭证更新或人工重启允许重新尝试。已提交任务保留原记录，不因断线重新提交。

备用、空闲扫描、认证和暂停通知共享持久化去重标记；同一未恢复故障不每小时重复发送。通知入队失败不写成已通知。暂停时优先使用原任务或当前队列的绑定路由发送说明，避免悄悄停连。恢复一次真实操作后重新允许下次故障通知。该机制抑制重复通知，通知写入与状态保存仍不是跨文件事务，崩溃窗口不能承诺通知 exactly-once。

`/check` 同时检查桥重连状态；已暂停或有连续失败时明确报告。桥进程心跳新鲜且为 live 模式仅证明进程在线，不能证明 Muse 连接可用，现显示“连接未验证”，不再据此报全部正常。

验证：新增重连策略 12 项、桥健康提示 4 项通过，包含真实 step/poll 和 idle history 故障、退避、凭证更新、原任务保留和通知去重。命令审计 59 项通过；最终 15 组沙箱套件共 194 项检查通过，编译及格式检查通过。仍需 Linux/systemd 与真实平台联调。
