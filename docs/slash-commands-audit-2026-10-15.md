# 斜杠命令审计（2026-10-15）

待办 25。对照对象是微信网关 `weixin-bot/gateway.py` 与企微网关 `wecom-bot/gateway.py` 的斜杠命令子系统：`SLASH_COMMANDS` 14 个命令，加上中文别名，`/help` 用两边共用的 `SLASH_HELP_TEXT`。审计时两边的用户可见文案已经是同一份；行为差集中在企微 `/queue clear`、`/queue drop` 没有忘掉到达反馈记录。下面「改前」是审计当时的说法，「处理」是这次改动。轮转、取消登记、审批决定本身没有改。

`/a`、`/b`、`/c` 的决定仍是 `allow_once`、`allow_always`、`deny`。

## 不一致与处理

1. `/new` 帮助和回执都说新会话已经开好。实际只写 `topic_boundary.json`。处理：改文案。写失败时回执改为没记下。
2. `/queue` 在冷通道空、桥上还有任务时，先说「队列空闲」，再补桥上的行。处理：改回执拼法。两边都空才说空闲。桥上正在跑的补上摘录。
3. `/queue drop bN` 能用，帮助只写了 `桥N`。`/approve`、`/deny`、`/approvals` 能用，帮助没写，而脚注说没列出的斜杠当普通消息。处理：补进帮助。
4. `/status` 摘要把后台续跑批次数写成「并行 N 条」，和总览里的「后台续跑」不是一回事，单位也不对（批，不是条）。桥状态文件读失败时，总览整段消失，冷通道行也没了。处理：摘要改为「后台续跑 N 批」；桥文件读失败时写明读不到，冷通道和副助手行仍列出。
5. `/stop` 回执对所有正在跑的消息都说「下一个进度检查点停下并回你一句确认」。冷通道工人提示词确实是下次进度检查时停，并回一句已取消。原生桥是下一轮 `chat.cancel`，代码里没有第二条确认。处理：改回执，哪一边有任务才说哪一边。登记全部失败时不再说已登记。
6. `/subagent` 回执在请求刚落盘时就说「已派发」「后台执行中」。钩子下一轮才启动，同时在跑的名额满了会排队。`/subagent stop` 对排队中的任务也承诺「下一个检查点停下并回一句确认」；排队中的是下一轮直接退出，不另发结果。正在跑的才会回「【副助手 #id 已停止】」。处理：改回执和帮助。
7. `/check` 里原生桥只要心跳在 30 秒内就打勾，shadow（未接管）也算通过，结论可以是「全部通过」。处理：改判定，心跳新鲜且该渠道为 live 才通过。
8. 企微 `/queue clear`、`/queue drop` 不从 `feedback_track` 去掉被删消息，微信会去掉。被删的桥上消息之后仍可能收到「开始处理」或久等提醒。处理：企微命令处理补上同样的忘记调用。

## 逐命令对照

| 命令 | 改前帮助 | 改前代码与回执 | 真实语义 |
|---|---|---|---|
| `/ping`（无别名） | 连通自检 | `pong ✅ {渠道}网关在线（状态…）· 时间 · 网关直接秒回，未唤醒任务` | 网关自己读 `status.json` 后秒回，不写队列、不唤醒工人。回执里的状态就是文件里的状态 |
| `/status` | 渠道状态 + 任务总览 | 摘要含「并行 N 条」；总览拼在后面。桥文件读失败时总览变成空字符串 | 摘要的 N 是冷通道后台续跑的批次数，这些消息已经算进「正在处理」。总览列桥、冷通道、后台续跑、排队、副助手和桥累计 |
| `/queue` | 队列明细，冷通道和原生桥都列 | 冷通道空就回「队列空闲…」，然后再把桥的摘要和排队摘录接在后面。桥上正在跑的只有条数和秒数，没有摘录 | 冷通道列在跑、排队、后台续跑。桥上列进行中和排队。两边都空才是空闲 |
| `/queue clear` | 清掉排队中未开工的，桥和冷通道一起清 | 回执「已提交清除…约 5 秒内生效。正在跑的任务不受影响。」微信同时忘掉反馈记录，企微不 | 只提交还没开工的排队。冷通道写 `queue_admin.json`，桥写 `queue_admin-{渠道}.jsonl`。正在跑的不动 |
| `/queue drop N` / `桥N` / `bN` | 只写了冷通道第 N 条和 `桥N` | `bN` 同样删桥上排队。冷通道回执不写「冷通道」。序号不对有报错。缺序号或多余词则整句不当命令 | 数字 N 只删冷通道排队。`桥N` 和 `bN` 删桥上排队。生效仍是提交后由钩子或桥下一轮执行 |
| `/stop` | 取消正在跑的任务 | 「已登记取消共 N 条，正在跑的任务会在下一个进度检查点停下并回你一句确认。」没有任务时说没有 | 取消冷通道在跑、后台续跑和桥上进行中的消息，不取消还没开工的排队。冷通道按工人提示词在下次进度检查时停并回一句已取消。桥下一轮直接 `chat.cancel`，不另发确认 |
| `/subagent`（别名 `/副助手`） | 派副助手并行执行；list 查，stop 停 | 派发回执「【副助手 #id 已派发】…后台执行中」。stop 一律「下一个检查点停下并回一句确认」。list 列运行、排队和最近 3 条结束 | 网关只把请求写入 `subagent_requests.jsonl`。钩子下一轮启动，同时在跑有上限，多的排队。排队中的 stop 下一轮直接退出。正在跑的 stop 登记取消，工人回「【副助手 #id 已停止】」 |
| `/new`（别名 `/新会话`） | 开新会话：换一个全新的原生会话 | 回执「已开新会话：之前的对话不会再带入上下文。」写文件失败也这么说 | 只写边界时间戳。桥在下一轮把会话标成待轮转，下一条走进桥的文字消息才 `session.start`。图片或不进桥的消息不会在网站上建出会话。冷通道下一次唤醒也不再带上边界之前的历史 |
| `/check`（别名 `/自检`） | 一次性自检，跑完即结束 | 六项检查，结果写入 `last_check.json`。原生桥心跳新鲜即打勾，shadow 也算通过 | 没有常驻定时器。shadow 表示桥没有接管这个渠道 |
| `/help`（别名 `/命令`） | 本命令表 | 回上面这份固定文案。未知斜杠（如 `/foo`）不拦截 | 文案必须覆盖实际会拦截的命令，包括英文审批名和 `bN` |
| `/审批`（英文 `/approvals`） | 只写了 `/审批`：待审批列表，出现时主动通知 | 读审批中继的 `state.json`，没有待办时说当前没有。英文命令能用但帮助没列 | 列表来自中继状态。主动通知由仓库外的 `approval_relay.py` 发送，本仓库看不到发送周期 |
| `/批` `/批准` `/approve` `/拒` `/拒绝` `/deny` `/a` `/b` `/c` | 帮助写了中文和 a/b/c，没写英文 | 回执「已提交{批准或拒绝} #N…执行结果马上发你。」重复提交会说已经交过 | `/a` 仅这次，`/b` 永久，`/c` 拒绝。`/批` 和 `/批准` 默认仅这次，后接「永」或「永久」才是永久。`/a` `/b` `/c` 忽略后面的「永」。决定写入 `decisions.jsonl`，由中继提交 |

## 改动文件

- `weixin-bot/gateway.py`、`wecom-bot/gateway.py`：帮助文案、`/new` `/queue` `/status` `/stop` `/subagent` `/check` 的回执或判定。企微补上 `/queue` 删除后的反馈记录清理。
- `tests/test_slash_commands_audit_20261015.py`：上述回执、帮助和审批字母映射。

没有改普通消息入站、桥的轮转与取消实现、出站发送，也没有改审批决定的三个取值。

## 遗留

- 「约 5 秒内生效」仍是近似说法。冷通道钩子注释大约 5 秒一轮，桥的轮询是 2 秒。没有改成更精确的数字。
- `/queue drop` 缺序号，或 `/queue` 后面不是 `clear` / `drop` 的已知形式，整句仍不当命令，会进普通消息。这是原注释里的既定分流，没有改。
- 审批回执「执行结果马上发你」，以及帮助里「新的审批出现时我会主动发通知」，依赖仓库外的审批中继。本仓库只能看到决定被追加进 `decisions.jsonl`，看不到中继的轮询周期，所以这两句没有改。
- `slash-commands-2026-10-04.md` 是当天的上线记录，里面的 `/new`、`/stop`、`/subagent` 回执仍是旧句。现行说法以两个网关的 `SLASH_HELP_TEXT` 和本审计为准。
